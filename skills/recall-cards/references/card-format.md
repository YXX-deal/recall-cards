# 卡片文件格式

卡片是 `cards/<id>.md`，由 YAML frontmatter（受控子集：标量、内联数组、`review` 一层嵌套）+ 固定正文小节组成。脚本按此格式解析，**不要改动字段名与小节名**。

设计原则：**一张卡只回答一个问题，只保留必要信息**。动机只存 frontmatter 一处，不在正文重复。

## Frontmatter 字段

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| id | 字符串 | `kc-YYYYMMDD-NNN`，用 `next-id` 生成 |
| title | 字符串 | 知识点短标题，≤ 20 字，不含标点结尾 |
| folder | 字符串 | 文件夹（课程级容器，**支持多级路径，用 `/` 分隔**），如 `计算机网络/数据链路层/STP`；缺省 `默认`，父级自动补全。与 category 是两个维度。管理台可重命名/移动子树/删除，卡片可跨文件夹移动 |
| category | 字符串 | 知识大类（图谱按此上色），如 `网络安全`、`园区网络`、`操作系统`；缺省时回退到二级/一级 tag。可手动改 |
| tags | 内联数组 | 2–4 个，学科/主题层级，如 `[网络, OSPF]` |
| keywords | 内联数组 | 检索词：同义词、英文缩写、易混写法 |
| created | 日期 | `YYYY-MM-DD` |
| status | 字符串 | `draft`（待确认草稿）或 `active`（已入库）。AI 回答后暂存的新卡为 `draft`，用户确认后转 `active`；手动新建默认 `active` |
| motivation | 字符串 | 一句话，**必须含场景**："做某套网络题库时分不清两个相近概念"。这是动机的唯一存放处 |
| source | 字符串 | 来源（题库/课件/论文/对话），无则留空 `""` |
| links | 内联数组 | 关联卡片 id，只通过 `link` 命令/接口维护（保证双向） |
| review | 嵌套 | 初始 `ease: 2.5, interval: 0, due: <created>, reps: 0, lapses: 0, last: ""`，之后只由 `record` 更新。调度遵循遗忘曲线：good 间隔 1→3→7→×ease，hard ×1.2 降 ease，forgot 重置 1 天扣 ease 计 lapse，ease 夹 1.3–3.0 |

## 正文小节（固定顺序，仅四个）

**问题与答案一律纯文本**：不用 `**加粗**`、`*斜体*`、`# 标题`、`` `代码` `` 等 Markdown 记号——这些记号在界面里会显示成刺眼的星号。脚本保存/显示时会自动清洗，但写入时就应干净。列表用 `- ` 短横即可。

```markdown
## 问题

<用户当时的原始问句，原样记录：不改写、不扩写、不补充背景>

## 答案

<浓缩要点：定义、关键机制、易错点。≤ 6 行纯文本列表，不整段复制对话，不附加用户没问的扩展>

## 关联

- [[<关联卡片id>]] <关系类型>：<可选一句说明>

## 复习记录

<由 record 自动追加，制卡时留空小节>
```

关系类型取 `前置 / 对比 / 应用 / 相关` 之一，图谱边标签取冒号前的类型词。例：`- [[kc-20261110-002]] 前置：先懂 SPF 才懂 LSA 泛洪的意义`。无说明时只写类型。

## 完整示例

```markdown
---
id: kc-20261117-001
title: OSPF 的 LSA 类型
folder: 路由交换
category: 路由交换
tags: [网络, OSPF, 路由]
keywords: [LSA, 链路状态通告, Type1, Type2, link state advertisement]
created: 2026-11-17
status: active
motivation: 做某套网络题库时，选项里的概念类型对不上号
source: 某套网络题库
links: [kc-20261110-002]
review:
  ease: 2.5
  interval: 0
  due: 2026-11-17
  reps: 0
  lapses: 0
  last: ""
---

## 问题

OSPF 里常见的 LSA 类型有哪些，各自谁产生、传多远？

## 答案

- Type1 Router LSA：每台路由器产生，仅本区域内泛洪
- Type2 Network LSA：DR 产生，描述本网段，仅本区域内
- Type3 Summary LSA：ABR 产生，区域间路由
- Type5 AS External LSA：ASBR 产生，全 OSPF 域（Stub 除外）
- 易错：Type4 通告 ASBR 位置，配合 Type5 使用

## 关联

- [[kc-20261110-002]] 前置：先懂 SPF 计算才懂 LSA 泛洪的意义

## 复习记录

```

## 维护规则

- **以知识点为单位判重**：制卡前跨整个库（含其他对话、含 draft）判断是否已有同一知识点的卡——问法不同但问的是同一个东西也算命中。命中则更新复用该卡（纠正/补全答案、补关联），**不新建**；同一知识点反复问只保留一张卡。只有确属新知识点才 `next-id` 新建。
- 手工编辑卡片后必须 `reindex`。
- 更新答案时保留 `## 复习记录`；答案被纠正过时，在答案末尾加一行"（YYYY-MM-DD 纠正：…）"。
- `links` 与正文 `## 关联` 保持一致：`link` 命令/接口维护 frontmatter 与关联行，关系说明可由你补写。
- 旧版卡片若含 `## 为什么问` 小节，编辑保存时会被自动移除（动机以 frontmatter 为准）。

## 草稿生命周期（先答后卡）

- AI 回答后暂存的新卡 `status: draft`：不进复习（`due` 排除）、不被检索反问命中（`search` 排除），只在管理台「待确认」托盘与图谱虚线圆中可见。
- 用户核对无误后 `confirm <id>`（或界面「确认入库」）：`status` 转 `active`，`review.due` 设为今天，开始进入复习调度。
- 用户纠错时直接改答案（保持 draft），确认后才入库；要丢弃则按删除流程。
- 手动在界面「新建卡片」默认 `active`，无需确认。
